# House style

The voice and visual language shared with [CVEGraphs](../CVEGraphs). Written down
here because most of the output in this repo is generated by code that runs
unattended once a month: if the rules only live in a person's head, the next
monthly run drifts off them.

## Prose (README, docs, commit messages)

- Bare repo or subject name as the H1. No emoji, anywhere.
- Open with one line saying what this is, then a short paragraph on why it exists.
- Sentence-case headings. No badge walls.
- A `File | Role` table beats an ASCII directory tree.
- Say what exists and what is rough. A "Status" section that only lists wins is
  marketing, not documentation.
- Skip the boilerplate sections: Contributing, Acknowledgments, Contact, License
  restatements, centered italic taglines.
- Link sibling repos by relative path.
- Close with: `Built on free CVE tooling from [RogoLabs](https://rogolabs.net).`

## Post copy (`post.txt`, `enriched_post.txt`)

Generated by `src/analysis/ytd_growth.py`. The formula:

1. Open on a one-sentence arguable claim. Not a statistic. The first line should
   be something a reader can agree or disagree with.
2. Put the load-bearing number in line two.
3. Keep it to about three tight paragraphs.
4. End on a genuine question, not a rhetorical one.

Hard rules:

- No em dashes.
- No `n=`. Spell it out: "373 CVEs".
- No decorative glyphs as bullets (`►`, `▶`, `✅`).
- Thousands separators on every count.
- Name the source: "Source: NVD, excluding rejected CVEs".
- Claims must survive a skeptic. State correlation as correlation. If a single
  month moved, do not describe it as a trend.

## Charts

Styling lives in `src/reports/style.py`. Do not hardcode colors or fonts in a
chart module.

- **Heading**: factual and descriptive, in Title Case. It states what the chart
  shows ("Cumulative CVEs Published, 2026 vs 2025"), never an argument or a
  verdict ("CVE growth is out of control").
- **Subtitle**: the reporting window and the single most important number.
- **Eyebrow**: `CVE INSIGHTS`, optionally with a suffix naming the view.
- **Palette**: the deep-navy ramp. Red is reserved for the highlighted series,
  which is the current year. Never decorative.
- **Type**: Host Grotesk headlines, Roboto body and labels, Roboto Mono for the
  eyebrow, the date stamp, and CVE ids.
- **Grid**: hairline, y-axis only, behind the data.
- **Stamp**: handle, site, and the date the chart was rendered, bottom right.
  Never the data-source date, so a chart never looks staler or fresher than the
  day it goes out. Provenance goes in the footnote, bottom left.
- **Ratios**: render wide, square, and portrait. One idea per chart, legible on a
  phone.
- Encode honestly: zero-based bars, no truncated axes, no area-scaled bubbles
  sized by radius.

## Alt text (`outputs/YYYY/alt_text.md`)

Generated by `src/reports/alt_text.py` from the same figures the charts are drawn
from, so the description cannot drift from the picture. Every chart that gets
posted gets alt text.

- Name the chart type and title, then describe the **shape**, not just the
  endpoints. "Cumulative CVEs, 2026 vs 2025" tells a screen reader user nothing
  about whether the lines converge or diverge.
- Carry the load-bearing numbers. They are not available any other way.
- Say which series is which colour and line style, because sighted readers get
  that from the legend.
- No middots or other decorative separators: they are silent. Use sentences.
- Name the source.
- Long form under 1,000 characters, which clears every platform's limit. A short
  form is generated alongside for the tightest ones.

## Reports (`outputs/YYYY/Month/Month.md`)

Written by `src/reports/generator.py`.

- Real headings, not the internal analysis keys.
- Numbers formatted for a human: thousands separators, two decimals at most.
- Tables, not bulleted key-value dumps.
- An empty analysis section is dropped, and the omission is logged. A bare
  heading with nothing under it reads as a quiet month when it usually means an
  analyzer returned nothing.
